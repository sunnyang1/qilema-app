## SOLID 原则检查

### SRP (Single Responsibility) - 单一职责原则

- 文件包含不相关的关注点（例如：HTTP + DB + 领域规则在一个文件中）
- 大类/模块，内聚性低或多个变更原因
- 函数编排许多不相关的步骤
- God objects（上帝对象）：知道系统太多信息
- **问自己**："这个模块变更的唯一原因是什么？"

### OCP (Open/Closed) - 开闭原则

- 添加新行为需要编辑许多 switch/if 块
- 功能增长需要修改核心逻辑而不是扩展
- 没有插件/策略/钩子点来支持变化
- **问自己**："能否在不触及现有代码的情况下添加新变体？"

### LSP (Liskov Substitution) - 里氏替换原则

- 子类检查具体类型或对基方法抛出异常
- 覆盖的方法弱化前置条件或强化后置条件
- 子类忽略或空操作父行为
- **问自己**："能否在不让调用者知道的情况下替换任何子类？"

### ISP (Interface Segregation) - 接口隔离原则

- 接口有许多方法，大多数实现者不使用
- 调用者依赖广泛的接口来满足窄需求
- 接口方法的空/存根实现
- **问自己**："所有实现者是否都使用所有方法？"

### DIP (Dependency Inversion) - 依赖倒置原则

- 高层逻辑依赖于具体的 IO、存储或网络类型
- 硬编码实现而不是抽象或注入
- 导入链将业务逻辑耦合到基础设施
- **问自己**："能否在不改变业务逻辑的情况下交换实现？"

## 常见代码异味（Beyond SOLID）

| 异味 | 迹象 |
|------|------|
| **长方法** | 函数 > 30 行，多层嵌套 |
| **特性依恋** | 方法使用来自另一个类的数据比自己的多 |
| **数据泥团** | 同一组参数重复传递 |
| **基本类型偏执** | 使用字符串/数字而不是领域类型 |
| **霰弹式修改** | 一个更改需要编辑许多文件 |
| **发散式变更** | 一个文件因许多不相关的原因而更改 |
| **死代码** | 不可达或从未调用的代码 |
| **投机泛化** | 为假设的未来需求而抽象 |
| **魔术数字/字符串** | 硬编码值没有命名常量 |

## 重构启发式方法

1. **按职责拆分，而非按大小** - 小文件也可能违反 SRP
2. **仅在需要时引入抽象** - 等待第二个用例
3. **保持重构增量** - 移动前隔离行为
4. **首先保持行为** - 重构前添加测试
5. **按意图命名** - 如果命名困难，抽象可能错误
6. **优先组合而非继承** - 继承创建紧密耦合
7. **使非法状态不可表示** - 使用类型强制不变量

## 安全与可靠性检查

### 输入/输出安全

- **XSS**：不安全的 HTML 注入、`dangerouslySetInnerHTML`、未转义模板、innerHTML 赋值
- **注入**：SQL/NoSQL/命令/GraphQL 注入通过字符串拼接或模板字面量
- **SSRF**：用户控制的 URL 在没有白名单验证的情况下到达内部服务
- **路径遍历**：用户输入在文件路径中没有清理（`../` 攻击）
- **原型污染**：JavaScript 中不安全的对象合并（`Object.assign`、用户输入的展开）

### AuthN/AuthZ

- 读写操作缺少租户或所有权检查
- 新端点没有 auth 守卫或 RBAC 强制
- 信任客户端提供的角色/标志/ID
- 访问控制破坏（IDOR - 不安全的直接对象引用）
- 会话固定或弱会话管理

### JWT & Token 安全

- 算法混淆攻击（接受 `none` 或在期望 `RS256` 时接受 `HS256`）
- 弱或硬编码的秘密
- 缺少过期（`exp`）或不验证它
- JWT 载荷中的敏感数据（令牌是 base64，未加密）
- 不验证 `iss`（发行者）或 `aud`（受众）

### Secrets 和 PII

- 代码/配置/日志中的 API 密钥、令牌或凭证
- git 历史或暴露给客户端的环境变量中的秘密
- 过度记录 PII 或敏感载荷
- 错误消息中缺少数据掩码

### 供应链与依赖

- 允许恶意更新的未固定依赖
- 依赖混淆（私有包名称冲突）
- 在没有完整性检查的情况下从不信任的源或 CDN 导入
- 具有已知 CVE 的过时依赖

### CORS & Headers

- 过于宽松的 CORS（`Access-Control-Allow-Origin: *` 带凭证）
- 缺少安全头（CSP、X-Frame-Options、X-Content-Type-Options）
- 暴露的内部头或堆栈跟踪

### 运行时风险

- 无界循环、递归调用或大内存缓冲区
- 外部调用缺少超时、重试或速率限制
- 请求路径上的阻塞操作（异步上下文中的同步 I/O）
- 资源耗尽（文件句柄、连接、内存）
- ReDoS（正则表达式拒绝服务）

### 密码学

- 弱算法（用于安全目的的 MD5、SHA1）
- 硬编码 IV 或盐
- 使用没有认证的加密（ECB 模式、无 HMAC）
- 密钥长度不足

### 竞态条件

竞态条件是导致间歇性失败和安全漏洞的微妙错误。需要特别注意：

#### 共享状态访问
- 多个线程/goroutines/异步任务在没有同步的情况下访问共享变量
- 全局状态或单例被并发修改
- 没有适当锁定的延迟初始化（双重检查锁定问题）
- 在并发上下文中使用非线程安全的集合

#### Check-Then-Act (TOCTOU)
- `if (exists) then use` 模式没有原子操作
- `if (authorized) then perform` 其中授权可能更改
- 文件存在检查后跟文件操作
- 余额检查后跟扣款（财务操作）
- 库存检查后跟订单放置

#### 数据库并发
- 缺少乐观锁定（`version` 列、`updated_at` 检查）
- 缺少悲观锁定（`SELECT FOR UPDATE`）
- 没有事务隔离的读-修改-写
- 计数器增量没有原子操作（`UPDATE SET count = count + 1`）
- 并发插入中的唯一约束违规

#### 分布式系统
- 共享资源缺少分布式锁
- 领导者选举竞态条件
- 缓存失效竞态（写入后读取陈旧数据）
- 事件排序依赖没有适当排序
- 集群操作中的脑裂场景

#### 需要标记的常见模式
```
# 危险模式：
if not exists(key):       # TOCTOU
    create(key)

value = get(key)          # 读-修改-写
value += 1
set(key, value)

if user.balance >= amount:  # Check-then-act
    user.balance -= amount
```

#### 要问的问题
- "如果两个请求同时访问此代码会发生什么？"
- "此操作是原子的还是可能被中断？"
- "此代码访问什么共享状态？"
- "这在高并发下如何表现？"

### 数据完整性

- 缺少事务、部分写入或不一致的状态更新
- 持久化前验证弱（类型强制问题）
- 可重试操作缺少幂等性
- 由于并发修改导致的丢失更新

## 代码质量检查

### 错误处理

#### 要标记的反模式

- **吞并异常**：空的 catch 块或仅记录的 catch
  ```javascript
  try { ... } catch (e) { }  // 静默失败
  try { ... } catch (e) { console.log(e) }  // 记录并忘记
  ```
- **过于广泛的 catch**：捕获 `Exception`/`Error` 基类而不是特定类型
- **错误信息泄露**：向用户暴露堆栈跟踪或内部细节
- **缺少错误处理**：没有 try-catch 包围可失败操作（I/O、网络、解析）
- **异步错误处理**：未处理的 promise 拒绝、缺少 `.catch()`、没有错误边界

#### 要检查的最佳实践
- [ ] 错误在适当的边界被捕获
- [ ] 错误消息对用户友好（不暴露内部细节）
- [ ] 错误记录足够的调试上下文
- [ ] 异步错误被正确传播或处理
- [ ] 为可恢复错误定义回退行为
- [ ] 关键错误触发警报/监控

#### 要问的问题
- "当此操作失败时会发生什么？"
- "调用者是否会知道出了问题？"
- "是否有足够的上下文来调试此错误？"

### 性能与缓存

#### CPU 密集型操作

- **热路径中的昂贵操作**：循环中的正则编译、JSON 解析、加密
- **阻塞主线程**：同步 I/O、没有 worker/async 的繁重计算
- **不必要的重新计算**：多次进行相同的计算
- **缺少记忆化**：相同输入重复调用的纯函数

#### 数据库与 I/O

- **N+1 查询**：循环中每项进行查询而不是批量
  ```javascript
  // 坏：N+1
  for (const id of ids) {
    const user = await db.query(`SELECT * FROM users WHERE id = ?`, id)
  }
  // 好：批量
  const users = await db.query(`SELECT * FROM users WHERE id IN (?)`, ids)
  ```
- **缺少索引**：未索引列上的查询
- **过度获取**：SELECT * 当只需要几列时
- **无分页**：将整个数据集加载到内存中

#### 缓存问题

- **昂贵操作缺少缓存**：重复 API 调用、DB 查询、计算
- **没有 TTL 的缓存**：无限期提供陈旧数据
- **没有失效策略的缓存**：数据更新但缓存未清除
- **缓存键冲突**：键唯一性不足
- **全局缓存用户特定数据**：安全/隐私问题

#### 内存

- **无界集合**：无限制增长的数组/映射
- **大对象保留**：持有引用阻止 GC
- **循环中的字符串拼接**：使用 StringBuilder/join 代替
- **完全加载大文件**：使用流代替

#### 要问的问题
- "此操作的时间复杂度是多少？"
- "这在 10x/100x 数据下如何表现？"
- "此结果可缓存吗？应该缓存吗？"
- "这可以批量处理而不是逐个处理吗？"

### 边界条件

#### Null/Undefined 处理

- **缺少 null 检查**：访问可能为 null 对象的属性
- **真值/假值混淆**：当 `0` 或 `""` 有效时使用 `if (value)`
- **过度使用可选链**：`a?.b?.c?.d` 隐藏结构问题
- **null vs undefined 不一致**：混合使用没有清晰约定

#### 空集合

- **不处理空数组**：代码假设数组有项目
- **空对象边缘情况**：空对象上的 `for...in` 或 `Object.keys`
- **第一个/最后一个元素访问**：`arr[0]` 或 `arr[arr.length-1]` 没有长度检查

#### 数值边界

- **除以零**：除法前缺少检查
- **整数溢出**：大数字超过安全整数范围
- **浮点比较**：使用 `===` 而不是 epsilon 比较
- **负值**：索引或计数不应该为负
- **差一错误**：循环边界、数组切片、分页

#### 字符串边界

- **空字符串**：不作为边缘情况处理
- **仅空白字符串**：通过真值检查但实际上为空
- **非常长的字符串**：没有长度限制导致内存/显示问题
- **Unicode 边缘情况**：Emoji、RTL 文本、组合字符

#### 要标记的常见模式

```javascript
// 危险：没有 null 检查
const name = user.profile.name

// 危险：没有检查的数组访问
const first = items[0]

// 危险：没有检查的除法
const avg = total / count

// 危险：真值检查排除有效值
if (value) { ... }  // 对 0、""、false 失败
```

#### 要问的问题
- "如果这是 null/undefined 会怎样？"
- "如果此集合为空会怎样？"
- "此数字的有效范围是什么？"
- "边界处（0、-1、MAX_INT）会发生什么？"
