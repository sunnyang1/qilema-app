## 审查摘要

```markdown
## Code Review Summary

**审查文件**：X 个文件，Y 行更改
**整体评估**：[APPROVE / REQUEST_CHANGES / COMMENT]
**审查维度**：SOLID 原则、安全与可靠性、性能、错误处理、边界条件、移除规划
```

## 发现的问题

### 优先级定义

| 级别 | 名称 | 描述 | 行动 |
|------|------|------|------|
| **P0** | Critical | 安全漏洞、数据丢失风险、正确性 bug | 必须阻止合并 |
| **P1** | High | 逻辑错误、重大 SOLID 违规、性能回归 | 合并前应该修复 |
| **P2** | Medium | 代码异味、可维护性关注、轻微 SOLID 违规 | 在此 PR 中修复或创建后续任务 |
| **P3** | Low | 风格、命名、次要建议 | 可选改进 |

### 输出格式

```markdown
## Findings

### P0 - Critical
(none 或列表)

### P1 - High
1. **[file:line]** 简短标题
   - 问题描述
   - 建议修复

### P2 - Medium
2. [继续跨部分编号]
   - ...

### P3 - Low
...
```

### 内联注释格式

```markdown
::code-comment{file="path/to/file.ts" line="42" severity="P1"}
问题描述和建议修复。
::
```

### 清洁审查

如果未发现问题，明确说明：
- 检查了什么
- 未涵盖的领域（例如，"未验证数据库迁移"）
- 残余风险或建议的后续测试

## 移除/迭代计划

```markdown
## Removal/Iteration Plan

### 安全立即删除

| 项目 | 位置 | 理由 | 影响 |
|------|------|------|------|
| [名称] | `path/to/file.ts:line` | 未使用的代码 | 无 |

### 延迟删除

| 项目 | 位置 | 前置条件 | 时间表 |
|------|------|----------|--------|
| [名称] | `path/to/file.ts:line` | 功能标志关闭 2 周 | 下一个冲刺 |
```

## 后续步骤

```markdown
## Next Steps

我发现了 X 个问题（P0: _, P1: _, P2: _, P3: _）。

**您希望如何继续？**

1. **修复所有** - 我将实施所有建议的修复
2. **仅修复 P0/P1** - 解决关键和高优先级问题
3. **修复特定项目** - 告诉我要修复哪些问题
4. **无更改** - 审查完成，无需实施

请选择一个选项或提供具体说明。
```

**重要**：在用户明确确认之前，不要实施任何更改。这是审查优先的工作流程。

## 完整示例

```markdown
## Code Review Summary

**Files reviewed**: 5 files, 120 lines changed
**Overall assessment**: REQUEST_CHANGES

---

## Findings

### P0 - Critical
1. **[src/auth.ts:45]** SQL 注入漏洞
   - 用户输入直接拼接进 SQL 查询，允许注入攻击
   - 建议修复：使用参数化查询
   ```typescript
   // 坏
   const query = `SELECT * FROM users WHERE id = ${userId}`
   // 好
   const query = `SELECT * FROM users WHERE id = ?`
   ```

### P1 - High
2. **[src/user.ts:78]** 竞态条件 - Check-Then-Act 模式
   - 余额检查后跟扣款，两个并发请求可能导致透支
   - 建议修复：使用数据库事务和原子操作

3. **[src/api.ts:123]** N+1 查询
   - 循环中每项执行一次数据库查询
   - 建议修复：使用批量查询 `WHERE id IN (...)`

### P2 - Medium
4. **[src/utils.ts:56]** 吞并异常
   - 空的 catch 块隐藏潜在错误
   - 建议修复：记录错误并适当处理

5. **[src/service.ts:89]** 违反 SRP 原则
   - Service 类同时处理 HTTP、DB 和业务逻辑
   - 建议修复：拆分为独立层

### P3 - Low
6. **[src/config.ts:12]** 魔术数字
   - 硬编码的超时值 `3000` 没有命名常量
   - 建议修复：定义为 `REQUEST_TIMEOUT_MS`

---
