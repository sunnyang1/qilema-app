# 测试套件重设计 PRD

## 1. 引言/概述

本 PRD 描述了对"起了吗 App"后端测试套件的全面重设计和优化。当前测试套件存在一些结构性问题，包括配置验证测试不匹配、缓存测试不稳定、以及部分集成测试依赖过于紧密。本重设计旨在提高测试的稳定性、可维护性和覆盖率。

### 要解决的问题

1. **测试失败率**：34/702 测试失败（约 4.8%），主要集中在配置验证和缓存相关测试
2. **测试依赖性**：部分测试过于依赖外部服务（Redis），导致测试不稳定
3. **配置验证不一致**：SECRET_KEY 和 DEBUG 配置的验证逻辑与实际实现不匹配
4. **测试覆盖率盲区**：某些关键功能（如熔断器持久化）缺乏充分的测试
5. **测试文档缺失**：缺乏清晰的测试策略和测试分类文档

## 2. 目标

- [ ] 将测试失败率降低至 1% 以下（7/702）
- [ ] 提高核心功能测试覆盖率至 90% 以上
- [ ] 建立清晰的测试分层策略（单元、集成、E2E）
- [ ] 实现所有测试的可重复运行（无外部依赖）
- [ ] 生成详细的测试报告（包含覆盖率、性能指标）
- [ ] 创建测试文档和最佳实践指南

## 3. 用户故事

### US-001: 修复配置验证测试

**描述**：作为开发者，我希望配置验证测试能够准确反映实际配置行为，以便及早发现配置错误。

- DEBUG 自动配置测试通过，开发/测试环境正确设置
- CORS 配置验证测试通过

### US-002: 修复缓存相关测试

**描述**：作为开发者，我希望缓存测试能够稳定运行，不依赖实际的 Redis 服务。

**验收标准**：
- 所有缓存服务测试使用 Mock，不依赖真实 Redis
- 缓存装饰器测试验证正确的缓存行为

- 缓存预热功能测试通过

## 4. 功能需求

### 4.1 测试组织

1. **测试目录结构**
   ```
   tests/
   ├── unit/              # 单元测试
   ├── integration/       # 集成测试
   ├── e2e/              # 端到端测试
   ├── fixtures/         # 共享夹具
   ├── conftest.py       # 全局配置
   └── README.md         # 测试文档
   ```

2. **测试标记定义**
   - `@pytest.mark.unit`: 单元测试（无外部依赖）
   - `pytest.mark.integration`: 集成测试（依赖测试数据库）
   - `@pytest.mark.e2e`: 端到端测试（完整用户流程）
   - `@pytest.mark.slow`: 慢速测试（运行时间 > 10秒）
   - `@pytest.mark.regression`: 回归测试

### 4.2 测试夹具

1. **数据库夹具**
   - `test_db`: 使用内存数据库的测试会话
   - `test_engine`: 测试数据库引擎
   - `clean_db`: 清理数据库的夹具

2. **Mock 夹具**
   - `mock_redis`: Mock Redis 客户端
   - `mock_notification_service`: Mock 通知服务
   - `mock_cache`: Mock 缓存装饰器

3. **数据夹具**
   - `sample_user`: 示例用户数据
   - `sample_health_record`: 示例健康档案数据
   - `sample_notification`: 示例通知数据

### 4.3 测试报告

1. **报告格式**
   - HTML 格式（pytest-html）
   - JSON 格式（pytest-json-report）
   - 覆盖率报告（pytest-cov）

2. **报告内容**
   - 测试执行摘要
   - 失败测试详情
   - 代码覆盖率统计
   - 性能指标

## 5. 非目标

- 不重写所有现有测试（优先修复失败的测试）
- 不添加性能基准测试（超出本次范围）
- 不实现测试自动化 CI/CD 集成（由 DevOps 团队负责）
- 不创建压力测试套件（已有独立的压力测试）

## 6. 设计考虑

### 6.1 测试隔离

- 每个测试应该独立运行，不依赖其他测试
- 使用测试数据库隔离数据
- 使用 Mock 隔离外部服务依赖

### 6.2 测试速度

- 单元测试应该在 10 秒内完成
- 集成测试应该在 30 秒内完成
- 端到端测试可以在 5 分钟内完成

### 6.3 测试可读性

- 测试名称应该清晰描述测试的目的
- 使用 Given-When-Then 模式组织测试代码
- 添加注释解释复杂的测试逻辑

## 7. 技术考虑

### 7.1 测试框架

- **pytest**: 主要测试框架
- **pytest-asyncio**: 异步测试支持
- **pytest-cov**: 代码覆盖率
- **pytest-html**: HTML 报告
- **pytest-mock**: Mock 支持

### 7.2 依赖项

- pytest==7.4.3
- pytest-asyncio==0.21.1
- pytest-cov==4.1.0
- pytest-html==3.2.0
- pytest-mock==3.12.0
- pytest-xdist==3.5.0（并行测试）

### 7.3 性能需求

- 单元测试套件总时间 < 5 分钟
- 集成测试套件总时间 < 10 分钟
- 端到端测试套件总时间 < 15 分钟

## 8. 成功指标

1. **测试通过率**: > 99%（至少 694/702）
2. **测试覆盖率**: 核心模块 > 90%，整体 > 80%
3. **测试运行时间**: 全量测试 < 30 分钟
4. **测试失败修复率**: 100%（所有当前失败的测试被修复）
5. **文档完整性**: 100%（所有测试都有文档说明）
