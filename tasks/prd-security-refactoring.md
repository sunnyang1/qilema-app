# 起了吗App - 安全配置重构PRD

## 1. 概述

### 1.1 项目背景
根据项目分析报告，起了吗App在安全配置方面存在严重的安全隐患，包括：
- SECRET_KEY使用默认值
- DEBUG模式在生产环境开启
- CORS配置过于宽松
- 缺少环境变量管理

这些安全问题可能导致：
- JWT Token被伪造
- 敏感信息泄露
- 跨域攻击风险
- 生产环境调试信息泄露

### 1.2 重构目标
修复所有安全配置漏洞，建立安全的生产环境配置体系。

## 2. 目标

- [x] 修复SECRET_KEY使用默认值的问题，生成并使用强随机密钥
- [x] 实现基于环境变量的配置管理（开发/测试/生产）
- [x] 修复DEBUG模式在生产环境开启的问题
- [x] 优化CORS配置，限制允许的来源
- [x] 添加.env.example模板文件
- [x] 添加环境配置验证

## 3. 用户故事

### US-SEC-001: 实现环境变量配置管理
**描述**：作为开发人员，我希望能够通过环境变量管理不同环境的配置，以便安全地部署到不同环境。

**验收标准**：
- 创建.env.example文件，包含所有需要的环境变量
- 修改Settings类支持从.env文件加载配置
- 添加环境变量验证逻辑
- 支持开发、测试、生产三种环境配置

### US-SEC-002: 生成强随机SECRET_KEY
**描述**：作为安全专家，我希望应用使用强随机的SECRET_KEY，以防止JWT Token被伪造。

**验收标准**：
- SECRET_KEY不再使用默认值
- 生成至少64字节的强随机密钥
- 提供密钥生成脚本
- 更新文档说明如何配置SECRET_KEY

### US-SEC-003: 根据环境配置DEBUG模式
**描述**：作为运维人员，我希望在生产环境自动关闭DEBUG模式，以防止敏感信息泄露。

**验收标准**：
- DEBUG模式通过环境变量ENVIRONMENT配置
- 生产环境（ENVIRONMENT=production）自动设置DEBUG=False
- 开发和测试环境可开启DEBUG
- 添加配置验证，防止生产环境意外开启DEBUG

### US-SEC-004: 优化CORS配置
**描述**：作为安全专家，我希望CORS配置更加严格，以防止跨域攻击。

**验收标准**：
- CORS允许的来源通过环境变量配置
- 生产环境只允许特定域名
- 避免使用"*"通配符
- 限制允许的HTTP方法和头部

### US-SEC-005: 添加环境配置验证
**描述**：作为开发人员，我希望应用启动时能验证配置的正确性，以便及早发现问题。

**验收标准**：
- 实现配置验证函数
- 应用启动时自动验证关键配置
- 配置错误时提供清晰的错误提示
- 支持可选配置和必选配置的区分

## 4. 非功能性需求

### 4.1 安全要求
- SECRET_KEY必须是强随机密钥（至少64字节）
- 生产环境必须关闭DEBUG模式
- 环境变量文件不应提交到版本控制
- 敏感信息不能出现在日志中

### 4.2 兼容性要求
- 兼容现有代码结构
- 不影响现有API接口
- 配置变更向后兼容

### 4.3 可维护性要求
- 提供清晰的配置文档
- 环境变量命名遵循约定
- 支持多种部署环境

- 不修改业务逻辑
- 不涉及前端应用

## 6. 设计考虑

### 6.1 环境变量设计
```
必需的环境变量：
- ENVIRONMENT: 环境（development/testing/production）
- SECRET_KEY: JWT密钥（64字节强随机）
- DATABASE_URL: 数据库连接字符串

可选的环境变量：
- DEBUG: 调试模式（根据ENVIRONMENT自动设置）
- CORS_ORIGINS: CORS允许的来源（逗号分隔）
- REDIS_URL: Redis连接字符串
- SMS_ACCESS_KEY: 短信服务访问密钥
- SMS_SECRET_KEY: 短信服务密钥
```

### 6.2 配置验证规则
- 生产环境必须设置非默认的SECRET_KEY
- 生产环境必须关闭DEBUG模式
- 数据库URL必须有效
- 环境变量格式必须正确

### 6.3 安全最佳实践
- .env文件添加到.gitignore
- 提供.env.example作为模板
- 敏感配置不在代码中硬编码
- 生产环境使用环境变量注入
