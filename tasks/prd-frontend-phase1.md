## 1. 引言

### 1.1 概述

Phase 1 目标是构建起了吗App的可运行基础版本，实现五大核心功能：用户认证、每日签到、SOS紧急求助、紧急联系人管理、健康档案管理。这些功能构成了应用的 MVP（最小可行产品）。

### 1.2 背景

后端 FastAPI 服务已完成，提供完整的 RESTful API。前端 Flutter 项目已创建，依赖已配置。现在需要实现前端功能以对接后端 API。

### 1.3 问题陈述

当前 Flutter 项目只有占位符代码，需要实现：
- 网络请求基础设施
- 用户认证流程
- 核心业务功能界面

---

## 2. 目标

### 2.1 主要目标

1. 搭建可复用的核心基础设施（网络、路由、主题）
2. 实现完整的用户认证流程（注册、登录、Token管理）
3. 实现每日签到打卡功能
4. 实现SOS紧急求助功能
5. 实现紧急联系人管理功能
6. 实现健康档案管理功能

### 2.2 成功标准

- 用户可完成注册、登录、每日签到
- 可触发SOS求助并查看状态
- 可管理紧急联系人（至少1个）
- 可填写和查看健康档案
- 基础路由和状态管理正常工作

## 3. 用户故事

### US-001: 配置核心基础设施

**描述**：作为开发者，我需要配置Dio客户端、拦截器、路由、主题，以便后续功能开发可以复用这些基础设施。

**验收标准**：
- Dio客户端能正常发送请求到后端API (http://localhost:8000/api/v1)
- 路由能正确跳转，认证守卫工作正常
- 主题能应用到整个App（浅色/深色模式）
- 控制台能输出结构化日志

### US-002: 实现登录页面

**描述**：作为用户，我能够通过手机号和密码登录到应用，以便使用应用的核心功能。

**验收标准**：
- 登录页面包含手机号输入框、密码输入框、登录按钮
- 登录成功后跳转到首页
- Token 自动保存到本地存储
- 显示友好的错误提示（密码错误、网络错误等）

### US-003: 实现注册页面

**描述**：作为新用户，我能够注册一个新账号，以便开始使用应用。

**验收标准**：
- 注册页面包含手机号、密码、昵称输入框
- 注册成功后自动登录并跳转到首页
- 密码输入时显示/隐藏切换功能
- 验证手机号格式和密码强度

### US-004: 实现Token管理和自动刷新

**描述**：作为系统，我需要管理用户的认证Token并自动刷新，以便用户的登录状态持久化且不会因为Token过期而中断使用。

**验收标准**：
- Token 存储在 SharedPreferences
- 401错误时自动刷新Token并重试请求
- Token刷新失败时跳转到登录页
- 所有API请求自动携带Authorization header

### US-005: 实现签到首页

**描述**：作为用户，我能够在首页点击签到按钮完成每日签到，以便确认我的安全状态。

**验收标准**：
- 首页显示大型签到按钮（蓝色"早安"按钮）
- 点击签到后按钮变为灰色"已签到"
- 显示今日签到状态（已签到/未签到）
- 显示连续签到天数和签到率统计

### US-006: 实现签到历史页面

**描述**：作为用户，我能够查看我的签到历史记录，以便了解我的签到习惯。

**验收标准**：
- 能查看最近7天/30天的签到历史
- 显示签到日期、时间、状态
- 支持下拉刷新和上拉加载更多
- 空状态提示（暂无签到记录）

### US-007: 实现SOS触发页面

**描述**：作为用户，我能够通过长按SOS按钮触发紧急求助，以便在危险时快速获取帮助。

**验收标准**：
- SOS按钮为红色圆形，长按3秒触发（防止误触）
- 长按时显示进度指示器
- 自动获取当前GPS位置
- 触发成功后跳转到SOS状态页面

### US-008: 实现SOS状态页面

**描述**：作为用户，我能够查看SOS求助的实时状态，以便了解救援进展。

**验收标准**：
- 显示SOS状态（待救援/救援中/已解除）
- 显示触发时间和位置信息

### US-009: 实现紧急联系人列表页面

**描述**：作为用户，我能够查看我的紧急联系人列表，以便了解我设置了哪些人会在紧急情况下被通知。

## 4. 功能需求

### 4.1 认证功能

1. **用户注册**：支持手机号、密码、昵称注册
2. **用户登录**：支持手机号、密码登录
3. **Token管理**：自动存储、刷新、携带Token

3. **签到历史**：查看历史签到记录

1. **SOS触发**：长按3秒触发SOS
2. **位置获取**：自动获取GPS位置
3. **状态追踪**：实时查看SOS状态
4. **拨打120**：一键拨打急救电话
5. **取消SOS**：可取消已触发的SOS

### 4.4 紧急联系人功能

1. **联系人列表**：查看所有紧急联系人
2. **添加联系人**：添加新的紧急联系人
3. **编辑联系人**：修改联系人信息
4. **删除联系人**：删除紧急联系人（至少保留1个）
5. **通知渠道**：选择短信/电话/App推送

### 4.5 健康档案功能

1. **基本信息**：查看和编辑基本信息
2. **病史管理**：添加、编辑、删除病史记录

## 5. 非功能需求

### 5.1 性能要求

- 页面加载时间 < 3秒
- 列表滚动流畅（FPS > 60）
- 网络请求超时时间：10秒

### 5.2 可用性要求

- 符合 Material Design 3 设计规范
- 适合老年人使用（大字体、高对比度、简单操作）
- 提供友好的错误提示

### 5.3 安全性要求

- Token 存储在 SharedPreferences
- HTTPS 通信（生产环境）
- 敏感信息不显示在日志中

### 5.4 兼容性要求

- Android 5.0+ (API 21+)
- iOS 12.0+
- 屏幕适配：4寸 - 10寸设备

## 6. 技术考虑

### 6.1 技术栈

- **Flutter 3.16+** (Dart 3.2+)
- **flutter_riverpod 2.4.0** - 状态管理
- **dio 5.4.0** - 网络请求
- **go_router 12.0.0** - 路由管理
- **shared_preferences 2.2.0** - 本地存储
- **Material Design 3** - UI组件

### 6.2 架构设计

采用分层架构 + Feature First模式：

- **Presentation Layer**: UI组件（Pages、Widgets）
- **State Management Layer**: Riverpod Providers
- **Service Layer**: API调用封装（Services）
- **Data Layer**: 数据模型（Models）

### 6.3 依赖关系

```
核心基础设施 → 认证模块 → 功能模块
```

### 6.4 网络请求规范

- 所有API响应使用统一格式：{code, message, data, timestamp}
- 200表示成功，非200为错误
- Dio拦截器自动提取data字段
- 错误统一抛出为DioException
