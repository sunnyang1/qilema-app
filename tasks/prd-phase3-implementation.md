# 起了吗App Phase 3 实施计划 - PRD文档

## 1. 概述

本文档定义了起了吗App从Phase 2过渡到Phase 3的完整实施计划，包括第三方服务接入和核心功能开发。

## 2. 目标

### 2.1 业务目标
- 将通知系统从模拟器升级为真实第三方服务，提高可靠性
- 实现急救知识库，提供专业的急救指导
- 扩展AED地图功能，完善急救资源覆盖
- 开发用药提醒功能，提升用户粘性
- 维持85%+测试覆盖率

### 2.2 技术目标
- 使用适配器模式接入极光推送、阿里云短信/语音、SendGrid邮件
- 实现服务熔断降级，确保系统稳定性
- 完成NotificationService、AnomalyService的BaseService重构
- 新增知识库、AED、用药提醒等服务，全部继承BaseService

## 4. 非功能性需求

### 4.1 性能要求
- API响应时间 < 500ms（P95）
- 第三方服务调用超时设置：推送3s，短信5s，电话10s，邮件5s
- 缓存命中率 > 80%

### 4.2 可靠性要求
- 第三方服务故障时自动降级到备用渠道
- 通知发送失败重试3次，间隔指数退避
- 所有定时任务执行成功率 > 99%

### 4.3 安全要求
- 第三方服务密钥存储在环境变量，不提交到代码库
- API密钥支持热更新（无需重启服务）
- 敏感操作（电话、短信）记录审计日志

## 5. 技术设计

### 5.1 通知适配器架构

```
app/core/notifications/
├── __init__.py
├── base_adapter.py          # 适配器基类接口
├── push_adapter.py          # 推送适配器
│   ├── __init__.py
│   ├── simulator.py         # 模拟器实现
│   └── jpush_adapter.py     # 极光推送实现
├── sms_adapter.py           # 短信适配器
│   ├── __init__.py
│   ├── simulator.py
│   └── aliyun_sms.py        # 阿里云短信实现
├── phone_adapter.py         # 电话适配器
│   ├── __init__.py
│   ├── simulator.py
│   └── aliyun_voice.py      # 阿里云语音实现
└── email_adapter.py         # 邮件适配器
    ├── __init__.py
    ├── simulator.py
    └── sendgrid_adapter.py  # SendGrid实现
```

### 5.2 知识库架构

```
app/models/knowledge_base.py      # 知识库模型
app/services/knowledge_service.py # 知识库服务
app/api/knowledge.py              # 知识库API
```

### 5.3 用药提醒架构

```
app/models/medication.py          # 用药相关模型
app/services/medication_service.py # 用药服务
app/api/medications.py            # 用药API
app/tasks/medication_tasks.py     # Celery定时任务
```

| P0 | US-005 | 架构基础，影响其他服务 |

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 第三方服务API变更 | 高 | 封装适配器层，隔离变化 |
| 第三方服务额度不足 | 高 | 实现额度监控和告警 |
| 新功能影响现有测试 | 中 | 保持向后兼容，渐进式迁移 |
| Celery定时任务故障 | 高 | 实现任务监控和失败重试 |
