# 服务层重构 PRD

## 1. 引言

### 1.1 目标
重构 "起了吗" App 后端服务层，解决当前架构中的关键问题，提高代码可维护性、可测试性和扩展性。

### 1.2 范围
- 后端服务层 (backend/app/services/)
- API 路由层 (backend/app/api/)
- 依赖注入容器 (backend/app/core/container.py)
- 模型层优化 (backend/app/models/)

### 1.3 背景
当前代码存在以下问题：
1. NotificationService 超过 1000 行，职责过重
2. 服务类方法类型混用（static/class/instance）
3. 依赖注入容器未充分利用
4. User 模型关联过多（18个关系）
5. 代码重复（缓存失效、查询模式）

---

## 2. 目标

### 2.1 主要目标
- 将 NotificationService 拆分为职责单一的多个服务
- 统一服务类设计模式（实例方法模式）
- 完善依赖注入机制
- 优化模型关联和查询性能
- 消除重复代码

### 2.2 成功指标
- 每个服务类代码行数 < 300 行
- 服务类方法类型统一
- 所有测试通过
- 性能无退化

## 6. 设计考虑

### 6.1 服务拆分策略
使用门面模式（Facade Pattern）：
- NotificationService 作为统一入口
- 内部委托给各子服务
- 对外保持 API 不变

### 6.2 依赖注入策略
- 服务类通过 __init__ 声明依赖
- Container 管理依赖生命周期
- API 层通过 Depends 获取服务

### 6.3 测试策略
- 每个服务独立测试
- 使用 mock 隔离依赖
- 集成测试验证协作
