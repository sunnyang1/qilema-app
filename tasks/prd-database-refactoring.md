# 起了吗App - 数据库重构PRD

## 1. 概述

### 1.1 项目背景
根据项目分析报告，起了吗App目前使用SQLite作为数据库，而PRD要求使用PostgreSQL。这限制了系统的扩展性和并发性能。

### 1.2 重构目标
将数据库从SQLite迁移到PostgreSQL，同时保持向后兼容，支持平滑迁移。

## 2. 目标

- [ ] 将数据库从SQLite迁移到PostgreSQL
- [ ] 支持PostgreSQL连接配置
- [ ] 创建数据库迁移脚本
- [ ] 保持现有数据完整性
- [ ] 更新文档和配置说明

## 3. 用户故事

### US-DB-001: 添加PostgreSQL支持
**描述**：作为开发人员，我希望应用支持PostgreSQL数据库，以满足PRD要求和提升性能。

**验收标准**：
- DATABASE_URL支持PostgreSQL连接字符串
- 数据库引擎自动识别数据库类型
- SQLite和PostgreSQL可切换
- 更新requirements.txt添加psycopg2依赖

### US-DB-002: 创建数据库迁移脚本
**描述**：作为运维人员，我希望有数据库迁移脚本，以便从SQLite迁移到PostgreSQL。

**验收标准**：
- 创建SQLite到PostgreSQL的迁移脚本
- 迁移脚本保持数据完整性
- 支持增量迁移
- 提供迁移回滚功能

### US-DB-003: 优化数据库配置
**描述**：作为开发人员，我希望数据库配置更加灵活，以便适应不同环境。

**验收标准**：
- 支持通过环境变量配置数据库连接
- 添加数据库连接池配置
- 优化数据库会话管理
- 添加数据库健康检查

### US-DB-004: 更新数据库初始化逻辑
**描述**：作为开发人员，我希望数据库初始化逻辑能适配PostgreSQL，以便正常使用。

**验收标准**：
- 移除SQLite特定的connect_args
- 数据库引擎初始化根据数据库类型调整
- 支持PostgreSQL特定功能（JSON、数组等）
- 数据库表创建优化

## 4. 非功能性需求

### 4.1 性能要求
- PostgreSQL连接响应时间 < 100ms
- 支持连接池（最小连接数5，最大连接数20）
- 支持数据库查询优化

### 4.2 可靠性要求
- 数据迁移零丢失
- 支持迁移失败回滚
- 数据库连接异常处理

### 4.3 兼容性要求
- 支持PostgreSQL 15+
- 保持SQLite作为开发环境的可选选项
- 现有API不变

## 5. 非目标

- 不涉及数据库结构修改（schema变更）
- 不涉及数据库分库分表
- 不涉及数据库读写分离
- 不涉及数据库监控和优化

## 6. 设计考虑

### 6.1 数据库连接配置
```
PostgreSQL连接字符串格式：
postgresql://user:password@host:port/database

SQLite连接字符串格式：
sqlite:///./qilema.db

环境变量：
- DATABASE_TYPE: 数据库类型（sqlite/postgresql）
- DATABASE_URL: 数据库连接字符串
```

### 6.2 迁移策略
- 导出SQLite数据为SQL脚本
- 转换为PostgreSQL兼容格式
- 导入PostgreSQL
- 验证数据完整性

### 6.3 兼容性处理
- 根据数据库类型动态调整配置
- SQLite特定功能使用条件判断
- 数据库类型检测和验证
