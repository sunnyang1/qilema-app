## 1. 项目概述

### 1.1 项目背景

"死了么"App作为一款针对独居人群设计的轻量化安全工具，以"每日签到+异常通知"为核心功能，精准击中了"独居意外无人知晓"的社会痛点。然而，该应用定位偏向"身后事"规划，存在功能局限：仅支持事后通知，缺乏实时救援能力。

"起了吗"App基于"死了么"的产品逻辑，将核心价值从"身后关怀"重构为"生命救援"，构建一个面向独居人群的紧急医疗服务平台。

### 1.2 项目目标

**核心目标**：
- 为独居人群提供可靠的紧急医疗救助通道
- 构建签到监测、异常预警、紧急求助、资源对接的完整安全闭环
- 打造操作简单、响应迅速、值得信赖的紧急医疗服务平台

### 1.3 用户群体

| 用户角色 | 描述 | 主要需求 |
|---------|------|---------|
| 独居青年（20-40岁） | 在一二线城市独自打拼的年轻人 | 快速急救、有人关注、低成本、易操作 |
| 独居老人（65岁以上） | 子女不在身边的空巢老人 | 简单易用、可靠通知、子女安心 |
| 异地子女 | 在外地工作的子女 | 远程了解父母状态、及时接收预警 |
| 高危职业人群 | 夜班工作者、高空作业等 | 安全监测、快速求助、实时定位 |
| 慢性病患者 | 需要长期监测的用户 | 健康档案、用药提醒、异常预警 |

## 2. 功能需求

### 2.1 核心功能模块

```
起了吗App功能架构
├── 用户认证与安全模块
├── 签到监测模块
├── 紧急联系人模块
├── SOS紧急求助模块
├── 健康档案模块
├── 智能设备联动模块
├── 急救资源对接模块
├── 消息通知模块
└── 用户设置模块
```

### 2.2 功能详细设计

#### 功能1：每日签到打卡

**功能描述**：用户通过每日签到确认自身安全状态，系统记录签到时间并在异常时触发预警机制。

**验收标准**：
- [x] 用户能够通过点击按钮完成每日签到
- [x] 签到成功后状态更新并保存到服务器
- [x] 每天仅首次签到有效
- [x] 签到历史记录能够查询

#### 功能2：异常预警机制

**功能描述**：当用户连续超过预设时间未签到时，系统自动触发预警流程，向紧急联系人发送通知。

**验收标准**：
- [x] 用户能够自定义预警时间阈值
- [x] 超过阈值未签到时自动触发预警
- [x] 预警通知能够通过多种渠道发送

#### 功能3：SOS紧急求助

**功能描述**：用户遇到危险或紧急情况时，可通过一键SOS快速发送求助信号。

**验收标准**：
- [x] SOS按钮长按3秒触发（防止误触）
- [x] 触发SOS后能够获取并发送当前位置
- [x] 求助通知能够通过多种渠道发送

#### 功能4：紧急联系人管理

**功能描述**：用户可以添加、编辑、删除紧急联系人，设置通知优先级和权限。

**验收标准**：
- [x] 用户能够添加紧急联系人（1-10个）
- [x] 能够设置通知优先级
- [x] 能够选择通知渠道

#### 功能5：健康档案管理

**功能描述**：用户可以记录个人健康档案信息，包括基础信息、病史、用药情况、过敏史等。

**验收标准**：
- [x] 用户能够填写完整的健康档案信息
- [x] 支持添加多条病史、用药、过敏记录
- [x] 健康档案加密存储

#### 功能6：智能设备联动

**功能描述**：支持绑定智能手环、手表等设备，实时监测用户生理数据。

**验收标准**：
- [x] 用户能够绑定智能手环/手表
- [x] 实时显示生理数据
- [x] 异常数据触发预警

#### 功能7：急救资源对接

**功能描述**：提供周边急救资源信息，包括120急救中心、社区医院、AED设备等。

**验收标准**：
- [x] 一键拨打120功能
- [x] 显示周边急救资源地图
- [x] 支持导航到最近的医院/AED

## 3. 数据设计

### 3.1 核心实体

**用户（User）**
| 字段名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| user_id | String | 是 | 唯一标识，UUID |
| phone | String | 是 | 手机号 |
| password_hash | String | 是 | 密码哈希值 |
| nickname | String | 否 | 昵称 |
| created_at | DateTime | 是 | 注册时间 |

**签到记录（CheckIn）**
| 字段名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| checkin_id | String | 是 | 唯一标识 |
| user_id | String | 是 | 用户ID |
| check_in_time | DateTime | 是 | 签到时间 |
| status | String | 是 | 签到状态 |

**紧急联系人（EmergencyContact）**
| 字段名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| contact_id | String | 是 | 唯一标识 |
| user_id | String | 是 | 关联用户ID |
| name | String | 是 | 姓名 |
| phone | String | 是 | 电话 |
| priority | Integer | 是 | 优先级 |

**健康档案（HealthRecord）**
| 字段名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| record_id | String | 是 | 唯一标识 |
| user_id | String | 是 | 用户ID |
| medical_history | JSON | 否 | 病史 |
| medications | JSON | 否 | 用药信息 |
| allergies | JSON | 否 | 过敏史 |

## 4. 技术规范

### 4.1 技术栈

#### 后端技术
- **语言/框架**：Python 3.11+ + FastAPI 0.104+
- **认证授权**：JWT + OAuth2.0
- **数据验证**：Pydantic
- **ORM**：SQLAlchemy 2.0+
- **缓存**：Redis 7+
- **数据库**：PostgreSQL 15+ / SQLite（开发环境）

#### 基础设施
- **容器化**：Docker + Docker Compose
- **CI/CD**：GitHub Actions
- **监控**：Prometheus + Grafana

### 4.2 服务层架构

所有核心服务继承 `BaseService[T]` 模式，提供统一的CRUD能力：

```python
class AlertService(BaseService[Alert]):
    model_class = Alert
    cache_prefix = CacheConfig.PREFIX_ALERT
    cache_ttl = CacheConfig.TTL_ALERT_LIST
```
