## 重构代码库模式

### 响应构建模式
- 使用ApiResponseBuilder统一构建API响应
- 消除路由层手动构建字典的重复代码
- 支持自动模型到Schema的转换

### 模型序列化模式
- 使用BaseModelMixin提供统一的to_dict/from_dict/to_schema方法
- 统一日期、枚举、空值处理
- 自动排除SQLAlchemy内部属性

### 服务层缓存模式
- 移除了不可靠的对象重建缓存机制
- 简化缓存策略：缓存字典用于存在性判断，实际对象从数据库获取
- 利用SQLAlchemy identity map优化重复查询

**重构模式:**
```python
# UserService 重构前 - 不可靠的缓存重建
@staticmethod
def get_user_by_id(db, user_id):
    cached = get_cached(f"user:id:{user_id}")
    if cached:
        user = User()
        for key, value in cached.items():  # 不可靠!
            setattr(user, key, value)
        return user
    # ...

# 重构后 - 使用 BaseService 统一缓存
@classmethod
def get_user_by_id(cls, db, user_id):
    return cls.get_by_id(db, user_id, pk_column="user_id")

# CheckInService 重构前
@staticmethod
def create_checkin(db, user_id, data):
    # ...
    invalidate_cache(CacheConfig.make_pattern(...))

# 重构后
@classmethod
def create_checkin(cls, db, user_id, data):
    # ...
    cls.invalidate_list_cache(f"{user_id}:*")
```

## 代码库模式 (Codebase Patterns)

### 服务层模式
- 所有服务应继承BaseService[T]，获得统一CRUD和缓存能力
- 静态方法保持向后兼容，内部调用实例方法
- 服务类定义: model_class, cache_prefix, cache_ttl 类属性

### 缓存模式
- 使用CacheConfig统一配置TTL和键前缀
- 键格式: {prefix}:{identifier}
- 写操作后需调用invalidate_cache清除相关缓存

### 通知适配器模式
- 适配器实现统一接口: send(), get_status()
- 支持通过环境变量切换模拟器/真实服务
- 真实服务失败时自动降级到模拟器

### 测试模式
- 单元测试使用pytest + SQLite内存数据库
- 集成测试使用真实API测试key
- 所有服务必须有对应的测试文件
